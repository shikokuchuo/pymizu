R interop

The process at the other end of a channel does not have to be Python. mizu is the R binding of the same shared-memory core, and a channel or pool connects the two languages directly.

R channel peers

A channel peer can be an R process with the mizu package installed. Pass the peer program as R source, and set the launcher to pymizu.r_launcher():

import pymizu

ch = pymizu.Channel.create(
    """
library(mizu)
repeat {
  x <- mizu_recv(ch, timeout = 30)
  if (inherits(x, "mizu_sentinel")) break
  mizu_send(ch, x)
}
""",
    launcher=pymizu.r_launcher(),
)

import numpy as np
ch.send(np.array([1.5, 2.5, 3.5]))   # arrives in R as a numeric vector
print(ch.recv(timeout=5))            # echoes back as a float64 array
ch.close()

r_launcher() needs R and the mizu R package installed. If either is missing, it raises MizuError before the channel is created. Pass rscript= to use a specific R installation.

To spawn the peer differently, write your own launcher: one callable that takes the channel’s token and starts the peer process. The reverse direction works too — an R session spawns a Python peer with mizu::mizu_py_launcher().

Mixed-language pools

A pool’s workers can be R processes. pymizu.r_pool_launcher() spawns them, and pymizu.call() describes the task: a qualified function name ("pkg::fn" for R, "mod.fn" for Python) or a source= string, plus constant arguments:

import numpy as np
import pymizu

pool = pymizu.Pool.create(4, launcher=pymizu.r_pool_launcher())
t = pool.submit(pymizu.call("stats::quantile", np.arange(101.0),
                            probs=np.array([0.25, 0.5, 0.75]), names=False))
print(t.collect())                  # [ 25.  50.  75.]
t2 = pool.submit(pymizu.call(source="y <- x * 2\ny + 1", x=20))
print(t2.collect())                 # 41
pool.stop()

Unnamed arguments become positional arguments, and keyword arguments become named ones, matching R’s calling convention. A source= task evaluates in a fresh environment with the keyword arguments bound as names and the positional arguments bound as _1, _2, … The result is the value of the last expression.

The workers’ language comes from the pool itself — there is no language argument and no override. On an R-worker pool, submitting a plain Python callable raises an error naming pymizu.call(). An unqualified name errors at submit. An argument that cannot cross the boundary raises DeclinedError at submit. An error in the R code crosses as TaskError with the R error type preserved in remote_type. A result with no Python equivalent fails the task with an error naming the type. The reverse direction mirrors: mizu::mizu_pool() with mizu::mizu_py_pool_launcher(), and mizu::mizu_submit_call() with mizu::mizu_call() specs.

Large arguments cross without copying. A fresh array argument past the zero-copy floor (a fixed size threshold) is written to shared memory once — one layout write — and the worker reads a view over it. An argument that is already a shared view (a _ShmView, or a numpy array whose .base chain ends in one) crosses as its identifier alone — zero payload bytes. If the pool runs workers too old to read such references, the submit fails with an error naming the remedy. A pool’s workers all run one language: mixing R and Python workers in one pool is not supported.

Mapping over a foreign pool

A pymizu.call() spec is also a map’s fn — Pool.map() and Pool.map_prepare() on an R-worker pool (and mizu::mizu_map() mirrors this in R):

pool = pymizu.Pool.create(4, launcher=pymizu.r_pool_launcher())
pool.map(pymizu.call("stats::median"), x)
pool.map(pymizu.call(source="summary(mgcv::gam(x$y ~ s(x$x)))$r.sq"),
         folds, template=0.0)   # each fold a dict; the element binds as x
pool.stop()

Each element fills the spec’s first positional argument (a named spec) or binds as x (a source= spec). Put constant arguments in the spec itself: the map’s own args=/kwargs= must stay empty. template= and collect= work unchanged, and a per-element error crosses with its index. Spec maps take integer seeds only (within R’s 32-bit range when the workers are R). Each language derives its own random streams from the seed, so results are reproducible for a given worker language but not identical across languages.

What crosses the language boundary

A portable subset of values crosses in both directions:

  • Python scalars (bool, int, float, complex, str, None), lists, and dicts with str keys cross both ways. R sees its own logical, integer, double, complex, character, and list values. A tuple arrives as a list.
  • A 1-D contiguous numpy array of any fixed-width numeric dtype arrives as an R vector, and an R vector arrives as a numpy array. See the dtype matrix below for the exact correspondence.
  • A large array crosses without copying: each side reads the other’s vector as a view over the shared pages. Without numpy, a received view is a buffer exporter, and any Arrow consumer wraps the shared pages zero-copy through the Arrow PyCapsule protocol: pa.array(view), pl.from_arrow(view).
  • A multi-dimensional numpy array arrives as an R array with dim set (a matrix is the 2-D case) — C order, F order, strided, it crosses value-exact. A large Fortran-order array also crosses without copying — R reads a matrix view over the shared pages; C-order and strided arrays cross by copy. datetime64 arrays with day or week units arrive as Date, and finer units arrive as POSIXct. datetime.date and datetime.datetime scalars arrive as the length-1 forms.
  • An Arrow array arrives as an R vector, with Arrow nulls as R missing values: ch.send(pa.array([1, None, 3])). Anything with __arrow_c_array__ works (pyarrow, polars, a duckdb result column).
  • An Arrow stream — a polars or pandas DataFrame, a pyarrow Table or ChunkedArray, a polars Series, a duckdb relation, anything with __arrow_c_stream__ — arrives as an R data.frame. Dictionary-encoded columns become factors, and date32/timestamp columns become Date/POSIXct. A Series arrives as a plain vector. An R data.frame arrives as a pymizu.Frame (below), and a factor as list[str | None].
  • bytes arrives as an R raw vector.
  • Strings cross both ways. R’s NA_character_ arrives as None, and a string vector arrives as list[str | None]. A large list[str | None] sent to R also crosses without copying — R reads a character vector over the shared pages, with None as NA_character_.
  • A value outside the portable subset raises pymizu.DeclinedError (a subclass of TypeError) at send time, with path and reason attributes naming what was rejected and why.

pymizu.Frame

A pymizu.Frame is Python’s home for an R data.frame: named columns with a row count. frame.to_dict() returns the columns as a dict — numpy arrays when numpy is installed, memoryviews otherwise, strings and factors as list[str | None]. frame.names and frame.row_names carry the metadata. Any Arrow consumer takes a frame in one line — pl.from_arrow(f), pa.table(f), pd.DataFrame.from_arrow(f) (polars >= 2.0 returns a struct Series for a streaming producer; .struct.unnest() restores the columns). Factors become dictionary columns, logicals Arrow bool, Date date32, and POSIXct timestamp[us]. A Frame pickles, so it crosses Python-to-Python channels. Sent to R, it becomes a data.frame again.

Data frames without copying

  • A large data.frame (past 32 KB) crosses as one shared-memory region in either direction. Python receives a region-backed Frame: its columns read directly from the shared pages, numeric columns as read-only numpy views. R receives an ordinary data.frame, read in place.
  • If the other side is too old to read these regions, the frame crosses as a copy instead — the value always arrives.
  • Sending a received frame back unmodified moves no data at all: it crosses as a reference to the region it arrived from. This holds through polars or pyarrow (pl.from_arrow(f), pa.table(f)) as long as no column was modified.
  • Modifying some columns moves only those columns. Each unmodified column still crosses as a reference, so a relay that adds one computed column pays for one column. R reads the unmodified columns as views of the original region.
  • A polars or pyarrow object that wraps a received frame keeps the frame’s shared-memory region alive until it is deleted and garbage-collected. Holding many of them at once can force later sends back to copying, so delete them when they are no longer needed.

Dates, times, and other types

  • A factor crosses as list[str | None] on its own, or as a dictionary-encoded column inside a frame.
  • A Date crosses as datetime64[D] or Arrow date32. A POSIXct crosses as a naive datetime64[us] or timestamp[us, tz]: microsecond precision, NaT read as NA. A named timezone is kept as frame column metadata but dropped from a standalone vector. Naive Python datetimes arrive in R with tzone = "UTC".
  • A difftime crosses as timedelta64[us]: microsecond precision, NA read as NaT. R’s five units cross by value; a round trip normalizes them to seconds. timedelta64 arrays of any non-calendar unit cross likewise (numpy scalars and datetime.timedelta included). Inside a frame, a difftime column exports to Arrow as duration[us], and an Arrow duration column arrives as a difftime.
  • A POSIXlt, Arrow date64/time/interval, and ordered dictionaries (polars Enums) are declined at send time.
  • An R vector with names is declined (numpy has no per-element names). A matrix crosses with values exact — the data is never transposed. dimnames and character matrices are declined.
  • Cross-language sends copy R’s ALTREP vectors by value: exact values, the compact representation is not preserved.

Missing values:

  • R marks missing values with sentinels inside the data: INT_MIN for integer and logical, INT64_MIN for integer64, and a special NaN value (NA_real_) for double. Arrow nulls convert to these sentinels, so R sees correct NAs.
  • Read from Python, the result depends on the accessor:
    • Copied reads (list(...), Frame.to_dict()) give honest dtypes: a logical arrives as bool_ when it has no NA, else int32; an integer arrives as int32 when NA-free, else float64 with NaN (every int32 value is exact in float64).
    • Zero-copy views keep the sentinel values in the buffer. .to_numpy() applies the same rule, reading NA-freeness off the region’s validity section before any data scan.
    • int64 keeps its dtype in every numpy form and warns when an NA is detected on a copied read or .to_numpy(). Use .to_arrow() for an NA-honest read. A genuine Python -2^63 value round-trips without a warning.
    • Every Arrow export of a logical is Arrow bool with a validity bitmap, whatever the path. Integer exports are int32 or int64 with a validity bitmap.
  • A genuine int32 value of -2147483648 collides with the NA sentinel and reads as NA in R. Likewise an int64 value of -9223372036854775808 reads as NA_integer64_. numpy sends stay silent. An Arrow int32 send with a validity bitmap warns once.
  • Python compute treats NA_real_ as an ordinary NaN. Whether the exact NaN value survives arithmetic is platform-dependent — do not rely on it.

Round trips are stable after the first hop, and a pass-through echo is bit-exact: an untouched received view sent back crosses as a reference to its region — no data moves — so even the NA_real_ value survives a relay. A slice or a dtype view of a received view crosses by value.

Between two Python processes — a channel or a pool — the conversions on this page never run: the identity dtypes cross unchanged and everything else pickles, so an exact Python-to-Python send of a non-identity dtype needs no work. They apply only when the other end runs R.
