Channels

A channel is a two-way message link between a Python process and a helper process that it spawns: one lock-free ring per direction, over shared memory. One process writes data and the other reads it in place — never copied through a socket, pipe, or file.

Creating a channel

Channel.create() spawns the peer process (python -m pymizu.child <token>) and connects both ends. The peer program is a Python source string, evaluated in the peer with ch bound to its side of the channel:

import pymizu

ch = pymizu.Channel.create("""
import pymizu
while True:
    x = ch.recv()
    if x is pymizu.CLOSED:
        break
    ch.send(x)
""")

The peer is a full Python process: it imports anything importable in the spawning interpreter’s environment. Channel.create() returns once the peer has attached (up to startup_timeout seconds, raising StartupError otherwise).

A launcher changes how the peer is spawned — it is one callable that takes the join token and arranges for a Python process to run python -m pymizu.child <token>. pymizu.r_launcher() is the built-in example: it spawns an R peer instead (see R interop). Channel.attach(token) is the low-level peer-side entry; user code spawns peers through a launcher.

Sending and receiving

ch.send() publishes a payload, visible to the peer the moment the call returns. Sends never block for ring space. ch.recv() returns the next payload, waiting up to timeout seconds (indefinitely when omitted):

ch.send([1, "a", None])
ch.recv(timeout=5)
[1, 'a', None]

Outcomes that end a conversation — ring full, timeout, orderly close, peer death — come back as sentinel singletons, never raised:

Sentinel Returned when
pymizu.FULL a send finds the ring full
pymizu.TIMEOUT a receive’s timeout expires
pymizu.CLOSED the peer has closed and the ring is drained
pymizu.PEER_GONE the peer process has died and the ring is drained

Test them by identity — x is pymizu.TIMEOUT — or with pymizu.is_sentinel(x). No call needs an error handler. If the peer dies, receives first drain what it already published, then report PEER_GONE.

send_batch() and recv_batch() move several payloads in one crossing — use them at rates where per-call overhead starts to matter:

ch.send_batch(range(4))
ch.recv_batch(4, timeout=5)
[0, 1, 2, 3]

ch.alive() reports whether the peer still runs, without touching the rings. ch.info() returns a read-only wire-state snapshot.

Closing

ch.close() is the orderly shutdown: it signals the peer and waits for it to finish draining before releasing the shared resources:

ch.close()
True

A channel is also a context manager — the with block closes it on exit. close_signal() signals without waiting; destroy() tears the handle down immediately and the peer sees PEER_GONE.

What crosses a channel

The staging path picks the first tier that matches:

  1. None crosses as an immediate — no bytes move.
  2. Buffer-protocol objects (bytes, 1-D contiguous numpy arrays) ride a serialization-free raw tier: float64, int32, int64, complex128, and uint8 cross unchanged, arriving as arrays (bytes arrives as uint8). A large buffer crosses as a zero-copy read-only view over the shared pages — no copy, no parse.
  3. A str within the inline budget crosses as raw UTF-8.
  4. Booleans, numbers, and flat containers of them ride a compact binary codec.
  5. Everything else crosses as a pickle protocol 4 stream.

Every handle knows its peer’s language (a per-region identity exchange at handshake). On a Python-to-Python channel that is the whole story: identity dtypes ride the raw tier, everything else pickles unchanged. On a foreign-language channel (an R peer), staging switches to the 'I' interchange stream: a portable subset crosses, and a value outside it raises pymizu.DeclinedError at send time, naming the value’s path and the reason — the channel is unharmed. See R interop.

An uncaught error in the peer crosses as a value, not a raised exception: a pymizu.TaskError carrying the original exception’s class name and traceback text. pymizu.is_remote_error(x) tests a received value; raise it to propagate.

Sizing

Channel.create() takes capacity (ring slots, a power of two), slot_size (bytes per slot — the inline payload budget is slot_size - 16), and arena_size (the channel’s spill arena). A payload past the inline budget spills to the arena or a fresh shared-memory region. spin=True selects pure-spin waiting: receivers never park to the OS — the lowest-latency mode, at full CPU use while waiting.
